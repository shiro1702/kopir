## Проблема

На части точек клиенты печатают **одни и те же документы** (бланки соцзащиты, заявления вуза, типовые формы копицентра). Сейчас каждый раз нужно:

1. Найти файл на телефоне / скачать с сайта
2. Отправить в бот
3. Оплатить и забрать

Для точки это трение; для партнёра — упущенный трафик «зашёл → сразу бланк».

---

## Решение

Каталог **готовых PDF на точке**. Клиент выбирает бланк в боте → заказ идёт по обычному флоу (копии → оплата → печать).

Файл уже на сервере: не нужен upload с телефона.

---

## Решения (зафиксировано)

| # | Вопрос | Решение |
|---|--------|---------|
| 1 | Где выбирает клиент | **Бот сначала** (TG/MAX); Mini App / сайт — позже |
| 2 | Кто управляет каталогом | **Spike: вручную** (Prisma / seed / super-admin later); ЛК партнёра — после валидации |
| 3 | Цена | **Как обычная печать**: `pageCount × copies × pricePerPageKopeks` точки |
| 4 | Когда | **Spike сейчас**: 1 точка, seed в БД + кнопка в боте |

## Spike scope (MVP-0)

### In

- Модель `PointTemplate` (см. ниже)
- PDF шаблона в Vercel Blob (`templates/{pointId}/{id}.pdf`), **не удалять** после печати
- При выборе бланка: **копия** blob → `orders/{orderId}.pdf` (как обычный заказ) → дальше существующий batch/оплата/агент
- В боте (TG + MAX через `bot/core`): при выбранной точке и непустом каталоге — кнопка **«Готовые бланки»**
- Список бланков точки → выбор → quote (страницы + цена) → копии → оплата как сейчас
- Seed / SQL для **одной** пилотной точки (без UI загрузки)

### Out (не в spike)

- ЛК партнёра: upload / rename / hide
- Super-admin UI
- Web / Mini App каталог
- Заполнение полей в бланке (формы)
- Глобальный каталог Kopir (общие бланки на все точки)
- Отдельный фикс-прайс или бесплатные бланки
- DOCX-шаблоны (только PDF)

## Модель данных

```prisma
model PointTemplate {
  id           String   @id @default(cuid())
  pointId      String
  point        Point    @relation(fields: [pointId], references: [id], onDelete: Cascade)
  title        String   // «Отчёт о выполнении программы соцадаптации»
  filePath     String   // Blob URL шаблона (постоянный)
  fileName     String   // original.pdf — для отображения / агента
  pageCount    Int
  sortOrder    Int      @default(0)
  isActive     Boolean  @default(true)
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  @@index([pointId, isActive, sortOrder])
}
```

`Order` не меняем: после копирования файла заказ неотличим от upload.

## UX бота (черновик)

После выбора точки / в главном меню точки (если есть активные шаблоны):

```
📍 Соцзащита, ул. …

[📄 Готовые бланки]
[📎 Отправить файл]
…
```

Список:

```
Готовые бланки — Соцзащита

1. Отчёт о выполнении программы соцадаптации (3 стр.)
2. Заявление на матпомощь (1 стр.)

[1] [2] [« Назад]
```

После выбора — тот же quote / копии / оплата, что после приёма PDF.

Если каталог пуст — кнопку не показывать.

## Технические заметки

1. **Не шарить `filePath` шаблона с заказом** — иначе `deleteOrderFile` после печати удалит общий бланк. Всегда `download` template → `uploadOrderFile` → новый order.
2. Логика в `bot/core` (TG + MAX сразу).
3. Точка обязательна: без `pointId` / last point — сначала выбор точки (UX-06), потом каталог.
4. `pageCount` и цена считаются при создании заказа из полей шаблона + тариф точки (`computeOrderAmountKopeks`).

## Критерии успеха spike

- [ ] На пилотной точке в боте видна кнопка и список ≥1 бланка
- [ ] Заказ из бланка оплачивается и печатается как обычный PDF
- [ ] Blob шаблона на месте после печати; у заказа — свой файл (удаляется как обычно)
- [ ] На точке без шаблонов UX не меняется

## Пилот (идея)

Точка с повторяющимися бланками (соцзащита, МФЦ-партнёр, вуз). Партнёр присылает PDF → мы кладём в Blob + seed `PointTemplate` → клиенты печатают из бота.
